# CFG-007 Research: AsyncIO Event Loop Binding Issue

## Problem Confirmed

The `_shutdown_event` in `downloader_throttle.py` is a module-level global `asyncio.Event` that causes `RuntimeError: <asyncio.locks.Event object at ...> is bound to a different event loop` when tests run with `pytest-asyncio` in strict mode (function-scoped event loops).

### Evidence
- Tests fail specifically when retry logic executes (line 100-108 in `downloader_throttle.py`)
- Error occurs at `await asyncio.wait_for(shutdown_event.wait(), timeout=delay)` 
- First test (`test_successful_response_on_first_attempt`) passes because it never hits the retry path with `shutdown_event.wait()`
- Tests requiring retry fail because the global Event was created in a different event loop

## Architecture Analysis

### Current Patterns in Codebase
1. **Class-based services**: `HttpClient`, `AdaptiveThrottle`, `HLSDownloader` all use instance-based state
2. **Function-based services**: `_retry_429_with_backoff`, `download_hls_with_resume` are module-level functions
3. **Global singletons**: Only `_shutdown_event` and `_active_processes` use module-level globals
4. **Signal handling**: `setup_signal_handlers()` called once per download session via `asyncio.run()`

### Usage Pattern
- `get_shutdown_event()` is called from:
  - `_retry_429_with_backoff()` in `downloader_throttle.py`
  - `download_hls_with_resume()` in `downloader.py`
  - `HLSDownloader.download_with_ffmpeg()` in `downloader.py`
  - `_download_with_ytdlp()` in `downloader.py`
  - `setup_signal_handlers()` in `downloader.py`

## Implementation Options Evaluated

| Option | Description | Pros | Cons |
|--------|-------------|------|------|
| A. Test fixture reset | Add `autouse` fixture to reset `_shutdown_event` in conftest.py | Minimal code change | Doesn't fix root cause, tests still fragile |
| B. Parameter injection | Pass `shutdown_event` as parameter to all calling functions | Clean architecture, explicit dependencies | Requires extensive refactoring across 5+ call sites |
| C. ContextVar pattern | Replace global with `contextvars.ContextVar[asyncio.Event]` | Maintains API compatibility, always loop-safe, Pythonic | Slightly more complex, requires understanding ContextVar |
| D. Module-scoped loops | Configure pytest to use module-scoped event loops | Zero code change | Reduces test isolation, affects all tests |

## Recommended Solution: ContextVar Pattern

Replace the module-level global with a `ContextVar` that lazily creates an `Event` bound to the current event loop:

```python
import contextvars

_shutdown_event_ctx: contextvars.ContextVar[asyncio.Event] = contextvars.ContextVar(
    "shutdown_event"
)

def get_shutdown_event() -> asyncio.Event:
    """Get the shutdown event for the current asyncio context."""
    try:
        return _shutdown_event_ctx.get()
    except LookupError:
        event = asyncio.Event()
        _shutdown_event_ctx.set(event)
        return event
```

### Why This Solution
- **Maintains backward compatibility**: No caller code changes required
- **Loop-safe by design**: Each event loop gets its own Event via lazy creation
- **Follows Python conventions**: `ContextVar` is the recommended pattern for context-sensitive globals (PEP 567)
- **Minimal implementation change**: Only 3 lines changed in `downloader_throttle.py`
- **No test modifications needed**: Tests will work without fixtures or scope changes
- **Production-safe**: Works correctly with `asyncio.run()` which creates fresh Event per `run()` call

### Implementation Steps
1. Replace `_shutdown_event: asyncio.Event | None = None` with `ContextVar` declaration
2. Remove the `global` declaration in `get_shutdown_event()`
3. Update `get_shutdown_event()` to use `ContextVar.get()` with try/except for LookupError
4. Replace `asyncio.TimeoutError` with built-in `TimeoutError` (Python 3.11+ convention)

- Confirmed root cause through test execution
- ContextVar pattern is documented Python best practice (PEP 567)
- Pattern successfully used in similar scenarios (web frameworks, ASGI servers)
- Compatible with existing class-based patterns in codebase (HttpClient, AdaptiveThrottle)
